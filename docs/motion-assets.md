# 动作素材技术规范（正式版）

给后续制作 `wave.webm` / `happy.webm` / `shy.webm` / `nod.webm` / `laugh.webm` / `dance_cute.webm` 用。
当前 `live/motions/dance_cute.webm` 只是**播放器测试片**（444×444，8 帧循环），不是正式素材。

## 1. 分辨率

- 推荐 **1080×1080**（方画布，人物居中）
- 最低 **720×720**；低于此在 1920 舞台放大后会糊（测试片 444 放大 2.1 倍已可见）
- 人物高度占画布 **85–92%**，脚底距底边 40–60px

## 2. 帧率

- **25 或 30 fps**
- 测试片只有 5.88fps（8 帧 GIF 转的），动作会一顿一顿

## 3. 透明背景

- 必须：**VP9 + alpha**（WebM 容器，`alpha_mode=1`）
- 不要用纯绿幕、不要用黑底+混合模式
- 验证方法：解码单帧看 alpha 是否 < 255；或在舞台上截图取视频区域角落像素，应该是背景色而不是黑色

## 4. 编码

```bash
ffmpeg -i input.mov -c:v libvpx-vp9 -pix_fmt yuva420p -b:v 3M -auto-alt-ref 0 -an dance_cute.webm
```

- VP9 profile 0，`yuva420p`，无音轨（`-an`）
- 码率 2–4 Mbps
- 不要用 H.264（不支持 alpha）

## 5. 起止姿势

- 首帧与尾帧都要回到**与立绘一致的待机姿势**，镜头、比例、朝向一致
- 这样播放结束切回 `character_v3.png` 时不会"跳一下"
- 循环类动作（如舞蹈）首尾帧应能直接衔接

## 6. 避免切换跳动

- 全片**不缩放、不位移**：人物脚底和头顶位置固定
- 相机不动；不要做推拉镜头
- 人物的水平中心始终在画布中线

## 7. 预加载

- 页面已设置 `preload="auto"`，打开舞台即开始预取
- 素材建议 ≤ 8MB，避免直播中途才加载完

## 8. 首尾帧 PNG

- 建议额外提供 `xxx.first.png` / `xxx.last.png`（透明 PNG）
- 用途：校验对齐、视频加载失败时兜底、快速预览
- 非必需，但做素材时顺手导一张成本很低

## 9. OBS 显示尺寸

- 舞台 1920×1080，角色显示高度约 **950px**
- 素材按 1080 高制作，页面会等比缩放，不需要改 OBS
- 视频宽度按 `auto` 自适应，不做拉伸（`object-fit: contain`）

## 10. 统一锚点与画布

- 画布统一 **1080×1080**
- 人物脚底中心固定在 **(540, 1040)**
- 所有动作素材共用这套锚点，换动作时不需要重新对位
- 与 `assets/character_v3.png` 的构图保持一致（同一套人物设定，不能换人）

## 附：当前播放器行为

- 视频正常：`<video>` 覆盖立绘播放，播完自动恢复立绘
- 视频缺失或解码失败：退回整图 CSS 摇摆（`sanwan-demo-dance`），**不会黑屏**
- 人工「停止动作」：立即 pause 并恢复立绘
- 唱歌期间：自动舞蹈被拒绝，不会中断歌曲
