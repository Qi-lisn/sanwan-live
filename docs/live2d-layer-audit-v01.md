# 三万 Live2D 分层素材审计（layer-draft V0.1）

素材包：`sanwan-layer-draft-v01.zip`
基准：`character_master_approved.png`（1052×1495，中立站姿，与直播用 `character_v3.png` 是两套姿势）
结论：**粗分层，不可直接绑定；真正挥手需要补绘。**

## 1. 包结构与完整性

| 检查项 | 结果 |
|---|---|
| 图层文件 | 10 张（native）+ 10 张（2x），全部存在 |
| 画布 | native 1052×1495，2x 2104×2990，全部一致 |
| 透明通道 | 全部 RGBA，alpha 正常 |
| 坐标对齐 | 所有图层同画布、同原点，叠加即还原母版 |
| OpenRaster | `sanwan_layer_draft.ora` 可解析：10 层，画布 2104×2990，无缺失引用；`mergedimage.png` 与 2x 母版**逐像素一致**（均值差 0.00） |
| 重合成 | 10 层按序合成 vs 母版：**均值差 0.00/255，差异>8 像素 0.00%** |
| 图层重叠 | 无（两两重叠 >3000px 的为 0）→ 是严格分区，不是叠层 |
| 白边/残留 | 边缘近白像素少量（多为白袜/白鞋/高光），**无成片抠图毛边** |
| 母版自身 | 头发区域近白像素 4.1%（高光，非噪点）；连通块 4 个，无游离碎片 |

> 分区干净是优点，但**分区干净 ≠ 可绑定**：所有图层互不重叠，意味着移动任一层就会露出透明。

## 4. 真正挥手可行吗？

**不能。** 现有素材只能做到「整块袖子绕肩旋转」，会立刻露馅。

程序化验证：把手臂层绕肩点 (403,411) 旋转，统计母版不透明区里变透明的像素：

| 旋转 | 空洞 | 说明 |
|---|---|---|
| 12° | 16,808 px | 占手臂层 40,260 px 的 **42%** |
| 25° | 25,351 px | 63% |
| 40° | 29,987 px | 74% |

空洞 = 「抬起来以后原本该有皮肤/衣料的地方现在什么都没有」。这就是**遮挡未补绘**。

### 挥手还缺什么

| 缺失 | 位置 | 要求 |
|---|---|---|
| 肩部底图 | (380–450, 390–470) | 手臂抬起后露出的肩膀、锁骨、腋下衣料 |
| 上臂/前臂分段 | 肘点约 (355,622) | 沿肘线切开，两侧各补 8–10px |
| 肘部内侧 | 肘点周围 ±40px | 弯曲时不被拉裂的内侧褶皱 |
| 手腕连接 | 手层 bbox (264,775)–(345,861) | 袖口与手掌之间的过渡像素 |
| 手型变体 | 手部 | 至少「张开」「并拢」「V 字」三张 |
| 袖子背面 | 整条袖子 | 抬臂后可见的袖内衬/阴影 |

## 7. 实现真正挥手的最小工作

1. **补绘肩部底图**（1 张，约 120×140px 区域）
2. **袖子沿肘切开**，补肘内侧与袖口（2 块）
3. **手型**：张开 / 并拢 / V 字（3 张，1024 宽级）
4. 把「上臂」「前臂」「手」分别导出为独立 PNG（同画布）
5. Cubism：3 个 Deformer（肩/肘/腕）+ 2 个参数（`ParamArmLA`、`ParamHandL`）+ 1 个 2.5s Motion
6. 验收：抬臂 60°、肘弯 45°、腕摆 ±15°，肩部无空洞、无拉裂

预计画师工作量：**2–3 天**（补绘 + 拆分），绑定 **1 天**。
